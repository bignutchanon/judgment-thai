## ผลตรวจคง EN 43 คีย์
ไล่ทีละคีย์ครบทั้ง 43 ตัว **ถูกต้องทั้งหมด**:
- ปุ่ม/สัญลักษณ์ tag (`<symbol=button_*>` เดี่ยว ๆ 7 คีย์) — คงไว้ถูกต้อง เพราะเป็น tag ไม่ใช่ข้อความ
- แบรนด์แพลตฟอร์ม (`PlayStation®4/5` · `Xbox One/Series X` · `PC` · `Stadia` · `Amazon Luna` · `Steam` · `Steam Store` · `Microsoft Store` · `Stadia store` · `console` · `Online ID` · `Gamertag` · `Steam ID` · `Stadia Name` · `PlayStation™Network` · `Xbox Live`) — เช็คย้อนกับ K3/Gaiden/Y6/K2R (`master_th.json` ทั้ง 4 โปรเจกต์) พบว่า `"console"` เก็บเป็น EN ดิบเหมือนกันทุกโปรเจกต์ (ไม่ใช่ error — เดิมสงสัยว่าควรทับศัพท์เป็น "คอนโซล" ให้เข้าชุดกับ `controller→คอนโทรลเลอร์`/`stick→สติ๊ก` แต่ตรวจ cross-project แล้วพบ `"console":"console"` ล็อกไว้ตรงกันทั้ง 4 โปรเจกต์เก่า จึงเป็นบรรทัดฐานเดิมที่ถูกต้อง ไม่ใช่จุดบกพร่อง)
- `SP` — ตรง §10 (ล็อกคง EN เปล่า ๆ)
- `aaaa` — debug placeholder ตรงเกณฑ์
- ชื่อ shape enum ของกล้อง/DOF/glare (16 คีย์: `gaussian`/`hexagon`/`bokeh`/`auto`/`cinematic`/`disable`/`bloom`/`lensflare`/`standard`/`cheaplens`/`afterimage`/`crossscreen`/`snowcross`/`sunnycross`/`horizontakstreak`/`verticalstreak`) — ค่า enum ภายในจาก `post_effect_dof_shapes.bin`/`post_effect_glare_shapes.bin` ไม่ใช่ข้อความที่ผู้เล่นเห็นตรง ๆ คงถูกต้อง
- ตรวจกลับด้าน (ควรคง EN แต่ถูกแปลไปแล้ว): **ไม่พบ**

## ข้อเสนอบรรทัดฐาน — `popup_frame.bin` (ฟีดโซเชียล/แชท)
`popup_frame.bin` เป็นบินใหม่ที่ไม่เคยมี batch ไหนแตะมาก่อน (เช็คแล้ว ไม่มีใน worklist/done ตัวอื่น) — นักแปล batch นี้เป็นคนตั้งบรรทัดฐานเองว่า **แปล display name เป็นไทย แต่คง `@handle` เป็นละตินทุกจุด** (เช็คครบ ~45 โพสต์ในบิน ไม่พบจุดหลุด) ตัวอย่าง: `"Tamazo the Drunk @Tamazo"` → `"ทามาโซ่ขี้เมา @Tamazo"`, `"Street Survivor @St_survivor"` → `"นักสู้ข้างถนน @St_survivor"`
- **เห็นด้วยว่าสมเหตุสมผล** — `@handle` คือ ID ระบบ/ชื่อบัญชีจริงที่ผู้เล่นอาจใช้ค้นหา/อ้างอิงในเกม เหมือนกันกับที่ `Chatter` (แอป SNS) ถูกล็อกคง EN ไว้แล้วใน §10 — ส่วน display name คือข้อความที่ผู้เล่นอ่านโดยตรง แปลให้เป็นธรรมชาติสมเหตุสมผลกว่า
- **เสนอ lead ล็อกเป็นกฎถาวรใน glossary** (แนะนำเพิ่มใน §10 หรือเปิด §14 ใหม่ "ศัพท์ฟีดโซเชียล/SNS"): "โพสต์ในฟีดแบบ popup_frame/Chatter → แปล display name เป็นไทย + คง `@handle` เป็นละตินเสมอ" เพื่อให้ batch อื่นที่มีฟีดแบบเดียวกัน (ถ้ามี) ใช้กฎเดียวกันโดยไม่ต้องเดาใหม่
- หมายเหตุ: hashtag ส่วนใหญ่คง EN (`#devilaragaki #jrock #indietop100`) ยกเว้น 1 จุดที่แปลเนื้อหาแฮชแท็กเป็นไทย (`#ladyhustlers` → `#สาวนักล่าเงิน`) — ไม่ถือว่าผิด เพราะเป็นแฮชแท็กสำนวนตลกของโพสต์เดี่ยว ๆ คนละลักษณะกับแฮชแท็กชื่อเฉพาะ/แนวเพลง แต่แจ้งไว้เผื่อ lead อยากให้เลือกแนวทางเดียวชัด ๆ (คง EN ทุกแฮชแท็ก หรือแปลได้ถ้าเป็นสำนวน)

## ความนิ่งของคำเรียก "สถานีตำรวจคามุโร" — **ไม่นิ่ง แจ้ง lead**
`position_stage_warp.bin` ใน batch นี้มีคีย์ `"Kamuro Police Station"` → นักแปลส่ง `"สถานีตำรวจคามุโร"` (ยืนยันว่า EN แยกจาก `Kamurocho PD Station` จริง — ไม่ใช่คำเดียวกัน ตรง `Kamurocho PD Station → สถานีตำรวจคามุโรโจ` ตามที่ glossary ล็อกไว้ (`translations/glossary.md:144`) — คำแปลของ batch นี้ถูกต้องตามกฎแยกคำ Kamuro/Kamurocho)

แต่เช็คกับ `master_th.json` ที่ ship แล้วพบว่า **สถานที่เดียวกัน (โรงพักคามุโรที่กล่าวถึงในบทพูด) ถูกเรียกไม่ตรงกัน 2 รูป**:
- `"He's the darling of\nthe Kamuro police station."` → `"เขาเป็นขวัญใจของ\nโรงพักคามุโรเลยละ"`
- `'He\'s the "hero"\nof the Kamuro police station.'` → `'เขาเป็น "ฮีโร่"\nของโรงพักคามุโร'`
- (เทียบกับ batch_125 ที่เป็นชื่อจุดวาร์ปบนแผนที่: `"Kamuro Police Station"` → `"สถานีตำรวจคามุโร"`)

**นี่คืออาคารเดียวกัน แต่ EN เขียนคนละสไตล์ (`Kamuro police station` ตัวเล็ก แบบบทพูด vs `Kamuro Police Station` ตัวใหญ่ แบบชื่อจุดบนแผนที่) และ TH ก็แปลคนละคำ (`โรงพักคามุโร` ในบทพูด vs `สถานีตำรวจคามุโร` ในชื่อจุดวาร์ป)** — ไม่ได้แก้ในไฟล์ batch_125 นี้เพราะ `"Kamuro Police Station"` (ตัวใหญ่ครบ) เป็นคำที่ไม่เคยมีมาก่อนในเกม และคำแปลที่ส่งมาก็ถูกตามกฎแยก Kamuro/Kamurocho — **ขอให้ lead ตัดสินว่าจะรวมเป็นรูปเดียว** (เสนอ: ใช้ "สถานีตำรวจคามุโร" เป็นชื่อทางการ (ป้าย/จุดวาร์ป) และคง "โรงพักคามุโร" ไว้เป็นคำเรียกลำลองในบทพูดได้ เหมือนภาษาไทยจริงที่คนพูด "โรงพัก" ปนกับ "สถานีตำรวจ" ได้ตามธรรมชาติ — แต่ต้องเป็นการตัดสินของ lead ไม่ใช่ QC ตัดสินเอง)

## ศัพท์ระบบต่อสู้ — ไล่ครบเทียบ batch 106
- `Evade` (ราก) → `หลบ` — พบใช้ในรูป `Evading Attacks` → `การหลบการโจมตี` ตรงกัน
- `Mortal Wound(s)` → `บาดแผลสาหัส` ✓ ตรงทุกจุด (2 ครั้ง)
- `Deadly Attacks` → `การโจมตีร้ายแรง` ✓ ตรงทุกจุด (3 ครั้ง)
- `Tiger Style` / `Crane Style` → `ท่าเสือ` / `ท่ากระเรียน` ✓ (ในบทเรียนนี้ใช้ราก "เสือ"/"กระเรียน" ในประโยคอธิบายสไตล์ ตรงกับรูปที่ ship แล้ว)
- `EX Action` → คง EN ✓ ทุกจุด
- `Cover Spot` → `จุดกำบัง` ✓ ตรง batch 106 — **แต่พบว่า master_th.json มีสตริงเก่าคู่ขนานที่แปล `Cover Spot` เป็น `"จุดกำบัง"` ในอีกบิน** (ข้อความเกือบเหมือนกันแบบคำต่อคำ ต่างแค่รายละเอียดปลีกย่อย) — เป็นความไม่นิ่งที่ ship ไปแล้วก่อน batch นี้ ไม่ใช่ของ batch_125 แต่ **แจ้ง lead ไว้เผื่อรัน normalize รอบใหญ่** (ของเก่าควรแก้เป็น `จุดกำบัง` ให้ตรง batch 106)
- `Emerge` → `โผล่ออกมา` ✓ ตรงทุกจุด (2 ครั้ง)

## พบเพิ่ม (ไม่เกี่ยวกับ batch นี้โดยตรง แต่ควรแจ้ง) — `Caution Gauge` ไม่นิ่งใน master ที่ ship แล้ว
ระหว่างเช็ค `Cover Spot` ไปเจอว่า `Caution Gauge` (ระบบสะกดรอย/tailing เดียวกับที่ใช้ `Emerge`/`Cover Spot`) ใน `master_th.json` มีคำแปลไม่ตรงกันถึง 3 รูป: `เกจระวังตัว` · `เกจระวังตัว` · `เกจระวังตัว` — ทั้งหมด ship ไปก่อน batch_125 แล้ว batch นี้ไม่มีคีย์ `Caution Gauge` ตรง ๆ จึงไม่กระทบ ตก 0 แต่ขอแจ้ง lead ไว้เผื่อจัดคิว normalize เพราะเป็นระบบเดียวกับที่บทเรียนนี้สอน (จะพาผู้เล่นสับสนถ้าจอ tutorial คำหนึ่ง แต่ป้าย HUD จริงอีกคำหนึ่ง)
